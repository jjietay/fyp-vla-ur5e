# Architecture A is a loop of one tool call per turn, with perception as a tool and a look after every skill

*30 Oct 2026:* renumbered from 0012, a number the five-cross ADR also took on another branch. `max_per_query` is now a count per phrase, and this design replaces ADR 0013.

Decided 26 Oct 2026, before any scored trial. Before this, A extracted its detector words once from the first transcript, so a clarification answer could never become new words (Tier 2: two `bottle` detections, and "orange juice" matched neither), and one planner reply could run pick and place before the pick was checked. Now the planner's first call must be `perceive(queries)`, which is the grounding step (ADR 0004), and it may look again with new words at any time. It also chooses `max_per_query`, how many boxes each phrase may keep, as a count per phrase (`{"bottle": 2}`; 1 for a phrase left out, capped by `detector.max_per_query`), so it can see two bottles when the task needs both without letting a false second cup in. Each reply holds one call, enforced with `disable_parallel_tool_use` and refused in `_read` as a backstop. After every skill, code looks at the table: after a pick or place that look is also the camera check, and its result goes back as `OK:` or `FAILED:` with the state. The state is kept in code (`state.py`): the held object by ID, the objects in view with IDs matched by position from look to look, and the objects out of view with no position, so a pick, a pour source or a drawer handle must aim at an object in view. The chat history is the run's only memory, bounded by `max_turns` (now 12), and is never summarised. Removed with the old design: `extract_queries`, the `queries=` debug bypass and `--no-reperceive`, since no open-loop A exists to compare against. This replaces the `look` tool of ADR 0013, which added words to a fixed grounding step: with `perceive` as a tool, choosing new words is the same call as the first. Recent modular systems do the same (ALRM, arXiv 2601.19510; MALLVi, arXiv 2602.16898). Trials recorded before this date are not comparable: grounding was a separate call, and each step had two captures (check and re-perceive) where it now has one.
