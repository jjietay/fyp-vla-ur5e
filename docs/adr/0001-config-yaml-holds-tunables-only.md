# config.yaml holds every tunable value, and six things stay in code on purpose

Every tunable lives in `config/config.yaml`, so that A and B cannot be constrained differently and the tests can see every limit. Values that are contracts or design, not tuning, stay in code: `STATE_NAMES`/`ACTION_NAMES`/`REQUIRED_DATASETS` (a checkpoint's format), `TASKS`/`CHANGELOG` in `suite.py` (the frozen experiment), the planner prompts (they *are* Architecture A), `TOOLS` (derived from the skill signatures and tested), `GRIPPER_OPEN`/`GRIPPER_CLOSED`, and the RG2 protocol numbers copied from `docs/rg2.script`. An edit to any of these in a config file would break something silently.
